# 在已安装 Pgy 的电脑上，把 Pgy 接进 WorkBuddy

**这份说明书面向使用者，不需要懂代码。全程大约 5 分钟。**

装完之后，你就可以在 WorkBuddy 的对话框里用大白话指挥 Pgy 干活了，比如：

> "看看 Pgy 现在连的是哪个账号、页面停在哪一步" · "截个图给我看" · "上次那批笔记投成功了吗"

---

## 先记住：谁该开着，谁该关着

这是最容易搞错的地方，先看这张表：

| 东西 | 装的时候 | 装完之后日常用 |
|---|---|---|
| **Pgy 客户端** | **开着**（建议）—— 安装最后会做一次自检，开着才能验证真的能用。开着就行，装的过程中不用动它 | **必须一直开着**（可以最小化，**不要点退出**） |
| **WorkBuddy** | **先关掉**——它可能正占用要替换的文件，导致安装失败 | 要用的时候开着，不用随便关 |
| 浏览器窗口 | 不用管（Pgy 自己会开一个） | 由 Pgy 自动打开，**全程显示在屏幕上**，别去关它 |

> **为什么 Pgy 必须一直开着？** WorkBuddy 这边只是个"传话的"，真正干活的是 Pgy 客户端里的本地服务。Pgy 一退出，本地服务就跟着关掉，WorkBuddy 里的工具立刻全部失联（会提示"连不上 Pgy 本地服务"）。最小化没问题，退出不行。
>
> **为什么装的时候要关 WorkBuddy？** 安装要把一个新程序文件放到固定位置。如果 WorkBuddy 正开着并且已经在用旧的同名文件，Windows 不允许覆盖，安装会失败（脚本会提示你先关掉 WorkBuddy）。

---

## 前提条件（花 1 分钟确认）

- [ ] 这台电脑**已经装好 Pgy 客户端**（能正常打开、能登录、能跑投放），版本 **0.9.11 或更新**
- [ ] 已经装好 **WorkBuddy 桌面版**，版本 **5.3 或更新**
- [ ] 拿到交付给你的那个文件夹，里面有这 4 个文件：
  ```
  pgy-mcp.exe            ← 要装的服务本体
  安装-pgy-mcp.cmd        ← 你要双击的就是这个
  install-pgy-mcp.ps1    ← 安装脚本本体（会被上面那个自动调用，别单独点它）
  mcp.json                ← 手动配置用的模板，跑脚本的话用不上
  ```

> **不需要**装 Node.js、Python，也不需要从别的什么"MCP 广场"下载东西——这个 exe 已经包含全部依赖。

---

## 第一步：装（双击一下）

1. **确认 Pgy 客户端是打开的**（能正常登录的那种状态；装的过程中不用动它，也别点退出）。
2. **把 WorkBuddy 完全关掉**（右上角关闭，确认托盘里也没有它）。
3. 双击 **`安装-pgy-mcp.cmd`**。
4. 如果弹出 Windows 的"未知发布者 / 是否允许"提示，选 **"仍要运行" / "允许"**。这个程序没有代码签名，属于正常现象。
5. 看到一串 `[OK]` 和最后一段"接下来只剩两步"就说明装好了。

脚本替你做了三件事（都不需要管理员权限）：

| 做了什么 | 放在哪 |
|---|---|
| 装好服务程序 | `%LOCALAPPDATA%\PgyMCP\pgy-mcp.exe` |
| 写好 WorkBuddy 的配置（自动合并，不会挤掉你已有的其它连接器；改之前会先备份） | `%USERPROFILE%\.workbuddy\mcp.json` |
| 跑一次自检，当场告诉你"现在能不能用" | — |

**此时 Pgy 的状态：应该开着。**
- 如果自检最后显示"已连上 Pgy 本地服务 / 会话可读"，说明一切就绪。
- 如果自检说"连不上"，**不影响安装成功**，只是说明 Pgy 没开着。把 Pgy 打开，然后重新双击一次 `安装-pgy-mcp.cmd` 再看一遍自检结果即可。

**此时 WorkBuddy 的状态：关着。**

---

## 第二步：在 WorkBuddy 里点一次「信任」（这一步必须手动做，脚本替不了）

**这一步不能省。** 安装脚本只把"服务定义"放好了，WorkBuddy 出于安全考虑，**新接进来的服务不会自动生效，必须由人在界面上确认一次**。只装不点的话，界面上要么看不到它、要么一直显示"失败"。

1. **打开 WorkBuddy**（现在才打开它，让它读取刚写好的配置）。
2. 找到管理自定义服务的页面。不同版本叫法不一样，常见的是「**自定义连接器**」或「**MCP 服务器**」。
   - **找不到就对了——最快的办法是直接在 WorkBuddy 的对话里问它**：
     > 我要添加/信任一个自定义 MCP 服务器，界面入口在哪个菜单？
     它知道自己的界面长什么样，比翻菜单快。
3. 在列表里找到名字是 **`pgy`** 的那一项。
   - 它可能显示为"未信任 / 失败 / 待确认"状态，**这是正常的**。
   - 如果列表里**完全找不到** `pgy`：先完全退出 WorkBuddy 再重新打开一次（配置是在 WorkBuddy 启动时读取的）。
   - 如果那个页面提供"添加/导入"的输入框，把下面这段直接贴进去保存（路径按你机器上的实际位置，`\\` 是两个反斜杠）：
     ```json
     {"mcpServers":{"pgy":{"type":"stdio","command":"C:\\Users\\你的用户名\\AppData\\Local\\PgyMCP\\pgy-mcp.exe","args":[]}}}
     ```
4. 点它旁边的 **「信任」**（有的版本写「启用」「允许」或「连接」）。WorkBuddy 会提示一句"首次连接此 MCP 服务需要您的信任确认"——点确认即可。
5. **重启当前会话，或者干脆新开一个会话**——工具是在会话开始时才注入的，光点信任不重开会话仍然看不到工具。

**此时 Pgy 的状态：必须开着**（WorkBuddy 要连它）。**WorkBuddy 的状态：开着。**

---

## 第三步：验证能用（两次，各 1 分钟）

**验证 1 —— 从命令行验（最准）：**

打开 Pgy，确认它在运行，然后在文件夹地址栏输入 `cmd` 回车，执行：

```
"%LOCALAPPDATA%\PgyMCP\pgy-mcp.exe" --self-test
```

应该看到：已连上的地址、当前账户、连接状态、以及 7 个工具名。看到这个就说明"底座是好的"。

**验证 2 —— 在 WorkBuddy 里验（最终确认）：**

在新的会话里说一句：

> 用 pgy 看一下当前状态，并截个图给我

它应该会调用工具，然后把账号、连接状态、以及一张浏览器页面的截图回给你。
**截图这一步是最有说服力的**——说明它真的"看得见"Pgy 管的那个浏览器窗口。

---

## 装完之后，日常使用时请记住三条

1. **浏览器窗口会全程显示在屏幕上，别去关它。** 那是 Pgy 实际干活的地方。你手动关掉它，正在进行的任务就断了。
2. **遇到人机验证 / 滑块 / 验证码，必须由你去那个浏览器窗口里点。** 程序（包括 WorkBuddy）不会、也不应该替你过验证。WorkBuddy 会提示你"平台要求验证，请到窗口处理"，你处理完告诉它继续即可。
3. **同一时间只能操作一个账户、一个任务。** 如果你在 Pgy 客户端里手动点了什么，WorkBuddy 这边同时发指令会撞车（会提示"已有操作正在进行"）。等一边做完再动另一边就行——这其实是好事，它保证了两边看的是同一份状态。

**账号仍然在 Pgy 客户端里添加和管理**：WorkBuddy 这边**有意不开放**加账号/改密码这类操作，因为那需要传密码，而密码不经过对话。

## 出问题怎么查

| 现象 | 原因与处理 |
|---|---|
| WorkBuddy 里 `pgy` 一直显示失败 | 还没点「信任」；或者点了信任但没重启会话。按第二步重来一遍 |
| 工具调用报"连不上 Pgy 本地服务" | Pgy 客户端没开着，或者被退出了。把它打开（最小化可以，退出不行） |
| **MCP 列表里完全找不到 `pgy`，也不报错** | ① 先确认配置里那一条有 **`"type": "stdio"`**（少了它会被静默丢掉，是本项目踩过的坑）；② 配置是在 WorkBuddy **启动时**读取的，完全退出 WorkBuddy（含托盘图标）再重开；③ 也可以用界面右上角的「**配置 MCP**」直接把配置粘进去保存——由它自己写入最保险 |
| 连接器列表里找不到 `pgy`（但配置看着没错） | 配置是在 WorkBuddy **启动时**读取的。完全退出 WorkBuddy（含托盘图标）再重开一次 |
| 双击安装脚本报"无法覆盖……多半是 WorkBuddy 正在使用它" | 完全退出 WorkBuddy 后重跑一次安装脚本 |
| 双击安装脚本报"现有的 mcp.json 不是合法 JSON" | 你的配置文件被手改坏了（例如写了注释、用了中文引号）。脚本**没有动它**，会打印一小段让你手动合并的内容。照它说的抄进去即可 |
| 安装脚本一开就闪退/被拦截 | 杀毒软件拦了新程序。把 `pgy-mcp.exe` 加入信任，或让 IT 放行后重跑 |
| 工具能列出但调用总是失败 | 用命令行那条 `--self-test` 先确认底座。如果自检正常而 WorkBuddy 里失败，多半是它连到了别的端口——确认 Pgy 客户端没有被改过端口 |
| 提示 409 / "已有操作正在进行" | 正常保护：一次只允许一个操作。等 Pgy 客户端里那个动作结束，或者等 WorkBuddy 上一个任务跑完 |

**如果 WorkBuddy 用的是"项目级"配置**（`<你的项目目录>\.workbuddy\mcp.json`，而不是用户目录那份），
把 `mcp.json` 的内容按同样方式合并进那一份即可。

## 不想跑安装脚本？手动配置

1. 自己把 `pgy-mcp.exe` 放到一个**不会随手删掉、路径里不含中文空格**的目录，
   例如 `%LOCALAPPDATA%\PgyMCP\pgy-mcp.exe`（用户目录，不需要管理员权限）。
   **不要**放进 `%LOCALAPPDATA%\Pgy\`——那是 Pgy 的安装目录，每次升级都会被整个清空。
2. 打开 `%USERPROFILE%\.workbuddy\mcp.json`，**合并**进下面这一段（不要整文件覆盖，
   别把已有的连接器挤掉；JSON 不支持注释）：
   ```json
   {
     "mcpServers": {
       "pgy": {
         "type": "stdio",
         "command": "C:\\Users\\你的用户名\\AppData\\Local\\PgyMCP\\pgy-mcp.exe",
         "args": []
       }
     }
   }
   ```
   > `command` 里的路径**必须**是你这台机器上 exe 的真实绝对路径，反斜杠要写两个 (`\\`)。
   > 交付文件夹里那份 `mcp.json` 里的路径是**带占位符的模板**，不能照抄——这也是推荐用安装脚本的原因。
   >
   > **`"type": "stdio"` 这一行不能省**（这是 2026-10-09 真机踩到的坑）：WorkBuddy 只把
   > `type` 为 `stdio` 的条目当成本地服务；少了它，这条会被**静默丢掉**——服务列表里
   > 什么都没有，也不报错、不写日志。要接的就是本机命令行程序，`type` 一定是 `stdio`
   > （只有你自己的程序起 HTTP 服务时才用 `http`）。
3. 之后同样要走第二步（点「信任」+ 重启会话）。

---

## 怎么卸载

1. 完全退出 WorkBuddy。
2. 删掉 `%LOCALAPPDATA%\PgyMCP` 整个目录。
3. 打开 `%USERPROFILE%\.workbuddy\mcp.json`，删掉 `mcpServers` 里的 `pgy` 这一段（保留其它连接器）。
4. 重开 WorkBuddy。

Pgy 客户端本身完全不受影响——这套东西只是"多接了一根线"，拔掉就回到原样。
