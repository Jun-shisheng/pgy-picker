# 在已安装 PgyPicker 的电脑上，把 PgyPicker 接进 MCP 客户端

**这份说明书面向使用者，不需要懂代码。全程大约 5 分钟。**

装完之后，你就可以在 MCP 客户端（下以 WorkBuddy 为例，其它支持 stdio MCP 的客户端同理）
的对话框里用大白话驱动 PgyPicker 选号了，比如：

> "看看 PgyPicker 现在连的是哪个账号、能不能开始检索" ·
> "列出蒲公英的一级行业" · "帮我检索母婴达人，每档 20 个" · "检索到哪一步了"

**PgyPicker 对蒲公英只读**：它只检索、采集、导出 Excel，不会发起邀约、建合作或投放。

---

## 先记住：谁该开着，谁该关着

| 东西 | 装的时候 | 装完之后日常用 |
|---|---|---|
| **PgyPicker 客户端** | **开着**（建议）—— 安装最后会做一次自检，开着才能验证真的能用 | **必须一直开着**（可以最小化，**不要点退出**） |
| **MCP 客户端（WorkBuddy）** | **先关掉**——它可能正占用要替换的文件，导致安装失败 | 要用的时候开着，不用随便关 |
| 浏览器窗口 | 不用管（PgyPicker 自己会开一个） | 由 PgyPicker 自动打开，**全程显示在屏幕上**，别去关它 |

> **为什么 PgyPicker 必须一直开着？** MCP 客户端只是「传话的」，真正干活的是
> PgyPicker 客户端里的本地服务。客户端一退出，本地服务就跟着关掉，
> MCP 里的工具立刻全部失联（会提示「连不上 PgyPicker 本地服务」）。最小化没问题，退出不行。

---

## 前提条件（花 1 分钟确认）

- [ ] 这台电脑**已经装好 PgyPicker 客户端**（能正常打开、能登录）
- [ ] 已经装好 **WorkBuddy 桌面版**，或其它支持 stdio MCP 的客户端
- [ ] 拿到交付给你的那个文件夹，里面有这 4 个文件：

```
pgy-mcp.exe            ← 要装的服务本体
安装-pgy-mcp.cmd        ← 你要双击的就是这个
install-pgy-mcp.ps1    ← 安装脚本本体（会被上面那个自动调用，别单独点它）
mcp.json                ← 手动配置用的模板，跑脚本的话用不上
```

> **不需要**装 Node.js、Python，也不需要从别处下载依赖——这个 exe 已包含全部依赖。

---

## 第一步：装（双击一下）

1. **确认 PgyPicker 客户端是打开的**（能正常登录的那种状态；装的过程中不用动它）。
2. **把 MCP 客户端（WorkBuddy）完全关掉**（右上角关闭，确认托盘里也没有它）。
3. 双击 **`安装-pgy-mcp.cmd`**。
4. 如果弹出 Windows 的「未知发布者 / 是否允许」提示，选 **「仍要运行」/「允许」**。
   这个程序没有代码签名，属于正常现象。
5. 看到一串 `[OK]` 和最后一段「接下来只剩两步」就说明装好了。

脚本替你做了三件事（都不需要管理员权限）：

| 做了什么 | 放在哪 |
|---|---|
| 装好服务程序 | `%LOCALAPPDATA%\PgyMCP\pgy-mcp.exe` |
| 写好 MCP 配置（自动合并，不会挤掉已有的其它连接器；改之前会先备份） | `%USERPROFILE%\.workbuddy\mcp.json` |
| 跑一次自检，当场告诉你「现在能不能用」 | — |

> 用的是别的 MCP 客户端时，把配置合并进那个客户端的 `mcp.json` 即可，内容相同。

---

## 第二步：在客户端里点一次「信任」

**这一步不能省。** 安装脚本只把「服务定义」放好了，客户端出于安全考虑，
**新接进来的服务不会自动生效，必须由人在界面上确认一次**。

1. 打开 MCP 客户端。
2. 找到管理自定义服务 / MCP 服务器的页面（不同版本叫法不同）。
3. 在列表里找到 **`pgy`**，点 **「信任」**（有的版本写「启用」「允许」或「连接」）。
4. **重启当前会话，或新开一个会话**——工具是在会话开始时注入的。

---

## 第三步：验证能用（两次，各 1 分钟）

**验证 1 —— 从命令行验（最准）：**

确认 PgyPicker 在运行，在文件夹地址栏输入 `cmd` 回车，执行：

```
"%LOCALAPPDATA%\PgyMCP\pgy-mcp.exe" --self-test
```

应看到：已连上的地址、当前账户、连接状态、以及 **5 个工具名**。

**验证 2 —— 在 MCP 客户端里验（最终确认）：**

在新的会话里说一句：

> 用 pgy 看一下当前状态

它应该会调用 `pgy_status`，把账号、登录态、能否开始检索回给你。

---

## 装完之后，日常使用时请记住三条

1. **浏览器窗口会全程显示在屏幕上，别去关它。** 那是 PgyPicker 实际干活的地方。
2. **遇到人机验证 / 滑块 / 验证码，必须由你去那个浏览器窗口里点。**
   程序（包括 MCP 客户端）不会、也不应该替你过验证。
3. **同一时间只能操作一个账户、一个任务。** 如果客户端里已有操作在跑，
   MCP 这边同时发指令会撞车（提示「已有操作正在进行」）。

**账号仍然在 PgyPicker 客户端里添加和管理**：MCP 这边**有意不开放**加账号/改密码，
因为那需要传密码，而密码不经过对话。

---

## 出问题怎么查

| 现象 | 原因与处理 |
|---|---|
| 客户端里 `pgy` 一直显示失败 | 还没点「信任」；或者点了信任但没重启会话 |
| 工具调用报「连不上 PgyPicker 本地服务」 | 客户端没开着，或被退出了。把它打开（最小化可以，退出不行） |
| **列表里完全找不到 `pgy`，也不报错** | ① 确认配置里有 **`"type": "stdio"`**（少了它会被静默丢掉）；② 配置是在客户端**启动时**读取的，完全退出后重开；③ 用界面里的「配置 MCP」直接粘贴配置 |
| 双击安装脚本报「无法覆盖」 | 完全退出 MCP 客户端后重跑一次安装脚本 |
| 双击安装脚本报「现有的 mcp.json 不是合法 JSON」 | 配置文件被手改坏了。脚本**没有动它**，会打印一小段让你手动合并的内容 |
| 安装脚本一开就闪退/被拦截 | 杀毒软件拦了新程序。把 `pgy-mcp.exe` 加入信任后重跑 |
| 工具能列出但调用总是失败 | 先跑 `--self-test` 确认底座；自检正常而客户端失败，多半是连到了别的端口 |
| 提示 409 /「已有操作正在进行」 | 正常保护：一次只允许一个操作。等上一轮结束再试 |

## 不想跑安装脚本？手动配置

1. 把 `pgy-mcp.exe` 放到一个**不会随手删掉、路径里不含中文空格**的目录，
   例如 `%LOCALAPPDATA%\PgyMCP\pgy-mcp.exe`（用户目录，不需要管理员权限）。
   **不要**放进 `%LOCALAPPDATA%\Pgy`——那是 PgyPicker 的数据目录，升级时可能被清空。
2. 打开对应客户端的 `mcp.json`，**合并**进下面这一段（不要整文件覆盖）：

```json
{
  "mcpServers": {
    "pgy": {
      "type": "stdio",
      "command": "C:\\Users\\你的用户名\\AppData\\Local\\PgyMCP\\pgy-mcp.exe",
      "args": []
    }
  }
}
```

> `command` 里的路径**必须**是本机 exe 的真实绝对路径，反斜杠要写两个 (`\\`)。
> 交付文件夹里那份 `mcp.json` 是带占位符的模板，不能照抄。
> **`"type": "stdio"` 这一行不能省**。

3. 之后同样要走第二步（点「信任」+ 重启会话）。

---

## 怎么卸载

1. 完全退出 MCP 客户端。
2. 删掉 `%LOCALAPPDATA%\PgyMCP` 整个目录。
3. 打开客户端的 `mcp.json`，删掉 `mcpServers` 里的 `pgy` 这一段（保留其它连接器）。
4. 重开客户端。

PgyPicker 客户端本身完全不受影响——这套东西只是「多接了一根线」，拔掉就回到原样。
